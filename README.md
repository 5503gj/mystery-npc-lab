# Mystery NPC Lab · 本地关系互动原型

包含三个原创推理场景（雾岛、车站、公寓）和《流芳》《野菩萨》关系机制演示。保持既有角色、页面和玩法；角色摘要不等于取得第三方内容的商业授权。

## 运行

Python 3.10+，无额外Python运行依赖：

```
python server.py
```

打开 http://127.0.0.1:7865/ ，关系页面为 /liufang.html 与 /ye-pusa.html 。
未运行本地模型时显示规则模式；不会自动下载模型或调用付费API。
可选设置 `MYSTERY_MODEL`、`OLLAMA_URL`、`MYSTERY_PORT`。
状态检查使用同一个配置的Ollama服务，并确认所选模型已安装。

仅需离线静态页面时：`python -m http.server 7863 --bind 127.0.0.1 --directory public`。
不要用项目根目录启动通用静态服务器。

## 结构与行为

- `public/catalog.js` 是角色、章节和线索的唯一数据源，同时由Python解析为可信场景目录。
- `public/common.js` 统一使用DOM文本渲染，不执行用户或模型返回的HTML；统一超时、取消与迟到响应校验。
- 对话按案件、章节、NPC、对话对象和服务器签发的会话分区。切换后旧请求不修改新视图。
- 客户端只能提交已知ID、问题与公开线索ID；不能提交system消息、历史、人设或任意关系规则。
- 服务端只把已公开线索正文交给模型，当前问题追加一次；最多保留最近8条成功模型消息。
- 关系值按双方独立保存，仅指定话题首次提问生效；尊重/选择分支有不同回复，重复提问不刷值。
- 仅服务public中的固定白名单文件，拒绝源码、隐藏文件、目录和穿越路径；会话cookie为HttpOnly/SameSite Strict。
- 问题最多1000字符，请求16KiB，模型并发2、响应64KiB、单会话64个对话、全局128个会话，闲置2小时后失效。
- 本地服务只监听127.0.0.1；跨来源POST被拒绝。模型失败显式返回错误并由页面显示规则回退。

## 企业实际使用前仍需完成

当前适合本机受控演示。公网服务需要真实身份认证、用户/租户授权、TLS、持久化会话与恢复、跨进程会话及任务队列、网关限流与观测。内存限额和cookie不是企业身份系统。

公开静态目录中仍可查看演示线索与结局，这是客户端演示的能力边界；正式付费推理游戏应将隐藏事实和进度解锁全部移到有权限的服务端。提示词不能保证消除模型幻觉或越界，需要冻结场景、真实模型评测及人工内容审核。
